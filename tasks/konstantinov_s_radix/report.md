## 1. Introduction
В данной работе рассматривается задача реализации алгоритма поразрядной сортировки (Radix Sort) для целых чисел типа `int`. Целью работы является разработка последовательного и параллельного (MPI) вариантов алгоритма, обеспечивающих корректную сортировку как положительных, так и отрицательных целых чисел, а также применение схемы простого слияния в параллельной версии.
Поразрядная сортировка для целых чисел отличается простотой реализации и линейной асимптотической сложностью. Использование MPI позволяет распределить вычисления между процессами и исследовать влияние коммуникационных издержек на общую производительность алгоритма.
## 2. Problem Statement
Требуется отсортировать массив целых чисел по возрастанию, используя поразрядную сортировку с простым слиянием.
### Входные данные:
- Неотсортированный массив целых чисел
### Выходные данные:

- Отсортированный входной массив
## 3. Baseline Algorithm (Sequential)
Последовательный алгоритм поразрядной сортировки для целых чисел типа `int` основан на обработке чисел по байтам:

1. **Побайтовая обработка:** Сортировка выполняется в несколько итераций по 8 бит, начиная с младшего байта. Для 32-битного целого числа требуется 4 прохода.
2. **Подсчёт частот:** На каждом проходе вычисляется количество вхождений каждого возможного значения байта (0–255).
3. **Префиксные суммы:** По массиву частот строятся префиксные суммы, определяющие итоговые позиции элементов во вспомогательном буфере.
4. **Стабильное перераспределение:** Элементы исходного массива переносятся во временный буфер в обратном порядке, что сохраняет стабильность сортировки.
5. **Обработка знака:** Преобразование и положительных и отрицательных чисел в положительные с помощью сдвига, чтобы сортировка была применима.

После каждого прохода содержимое временного буфера копируется обратно в основной массив.
Асимптотическая сложность алгоритма составляет $O(4 \times N)$, что эквивалентно $O(N)$.

## 4. Parallelization Scheme
Параллельная версия алгоритма реализуется с использованием библиотеки MPI и состоит из следующих этапов:
1. **Распределение данных:** Исходный массив на процессе с рангом 0 разбивается на блоки и распределяется между всеми процессами с помощью `MPI_Scatterv`. Размеры блоков могут отличаться не более чем на один элемент.
2. **Локальная сортировка:** Каждый процесс выполняет последовательную поразрядную сортировку своего локального блока данных.
3. **Простое слияние:** Отсортированные блоки объединяются попарно по логарифмической схеме. На каждом шаге один процесс отправляет свой массив соседнему процессу, а принимающая сторона выполняет слияние двух отсортированных последовательностей.
4. **Завершение:** После завершения всех шагов слияния полностью отсортированный массив находится на процессе с рангом 0.

## 7. Conclusions
Накладные расходы на параллелизацию отнимают немного больше ресурсов, чем даёт параллелизация, что приводит к отсутствию и последующему снижению ускорения с ростом числа процессов. И без того плохо подходящий для параллелизации алгоритм (много данных, мало операций) становится ещё хуже при делении данных между процессами - количество обрабатываемых отдельным процессом данных снижается, при этом добавляются расходы на слияние.
